
# Day 4 – Structured Output Using Pydantic and JSON

## 1. Overview

This program extracts structured customer information from unstructured text using an LLM and validates the generated JSON using Pydantic.

The main objective is to convert normal customer text into structured data containing:

- Name
- Email
- Issue
- Phone number

## 2. Understanding Schema

A **Schema** defines the structure and expected data types of information.

In this project, we define a schema using a Pydantic model:

```
from pydantic import BaseModel

class Ticket(BaseModel):
    name: str
    email: str
    issue: str
    phone_no: int
```

### How does it work?

- `Ticket` is a Pydantic model.
- `name: str` means name must be a string.
- `email: str` means email must be a string.
- `issue: str` means issue must be a string.
- `phone_no: int` means phone number must be an integer.

The schema tells the LLM what structure we expect in the output.

## 3. Generating JSON Schema

```
schema = Ticket.model_json_schema()
```

`model_json_schema()` automatically converts the Pydantic model into a JSON Schema.

It describes:

- Expected field names.
- Expected data types.
- Required fields.

We include this schema in the system prompt so the LLM knows the expected output structure.

**Important:** JSON Schema describes the expected structure. It is not the actual extracted customer data.

## 4. Understanding System Prompt and Schema

```
system_prompt = f"""
Extract the personal information from the ticket strictly based on this schema and give a JSON output.
{schema}
"""
```

Here, the schema is inserted into the system prompt using an f-string.

The LLM receives instructions about which information to extract and how to structure it.

## 5. Understanding JSON Response Format

```
Response_format = {
    "type": "json_object"
}
```

This tells the API to generate its response in JSON object format.

It helps produce structured output instead of ordinary conversational text.

**Difference:**

- Schema defines the expected structure.
- JSON response format requests JSON output.
- Pydantic validates the generated data against the model.

## 6. Understanding Tokens

A token is a basic unit of text processed by an LLM.

A token can represent:

- A complete word.
- Part of a word.
- A number.
- Punctuation or special characters.

### Where are tokens used in this project?

The LLM processes:

1. System prompt and schema.
2. Customer ticket text.
3. Generated JSON response.

All of these contribute to token usage.

### Token categories

| Token             | Meaning                           |
| ----------------- | --------------------------------- |
| Prompt Tokens     | Tokens sent to the model as input |
| Completion Tokens | Tokens generated by the model     |
| Total Tokens      | Combined input and output tokens  |

**Formula:**

`Total Tokens = Prompt Tokens + Completion Tokens`

A larger schema or longer customer ticket can increase input token usage.

To check token usage, add:

```
usage = Response.usage

print("Input Tokens:", usage.prompt_tokens)
print("Output Tokens:", usage.completion_tokens)
print("Total Tokens:", usage.total_tokens)
```

## 7. Converting JSON String into Python Data

After receiving the LLM response:

```
answer = Response.choices[0].message.content
```

The variable `answer` contains the generated JSON as a string.

Example:

```
{
    "name": "Chandrahas",
    "email": "chandrahaskori8@gmail.com",
    "issue": "iPhone is not working",
    "phone_no": 89567829347
}
```

However, this is initially a string, not a Python dictionary.

### Step 1: Import JSON

```
import json
```

The JSON library helps convert JSON strings into Python objects.

### Step 2: Store the JSON response

```
raw_json = answer
```

Stores the LLM-generated JSON string in a variable.

### Step 3: Convert JSON into a Python Dictionary

```
data_file = json.loads(raw_json)
```

`json.loads()` parses a JSON string and converts it into a Python dictionary.

For example:

```
data_file["name"]
data_file["email"]
```

These expressions access values using dictionary keys.

## 8. Converting Dictionary into a Pydantic Object

```
ticket = Ticket(**data_file)
```

This is an important concept.

- `Ticket` is the Pydantic model.
- `data_file` is the dictionary.
- `**` unpacks the dictionary into keyword arguments.
- Pydantic validates the supplied fields and their data types.

For example:

```
ticket = Ticket(
    name="Chandrahas",
    email="chandrahaskori8@gmail.com",
    issue="iPhone is not working",
    phone_no=89567829347
)
```

Both approaches create a Pydantic object.

## 9. Extracting Individual Variables

After creating the Pydantic object, we can access individual fields using dot notation.

```
print(ticket.name)
print(ticket.email)
print(ticket.issue)
print(ticket.phone_no)
```

| Expression        | Extracted Information |
| ----------------- | --------------------- |
| `ticket.name`     | Customer name         |
| `ticket.email`    | Customer email        |
| `ticket.issue`    | Customer issue        |
| `ticket.phone_no` | Customer phone number |

**Remember:**

- `data_file["name"]` accesses a dictionary value.
- `ticket.name` accesses a Pydantic model attribute.

## 10. Complete Workflow

1. Define a Pydantic model.
2. Generate its JSON Schema.
3. Pass the schema to the LLM through the system prompt.
4. Send customer text to the LLM.
5. Receive structured JSON output.
6. Store the response in `answer`.
7. Use `json.loads()` to convert JSON text into a Python dictionary.
8. Use `Ticket(**data_file)` to create and validate a Pydantic object.
9. Extract individual fields using dot notation.

## 11. Key Learning Outcomes

| Concept               | Purpose                                            |
| --------------------- | -------------------------------------------------- |
| Pydantic Schema       | Defines expected data structure                    |
| `model_json_schema()` | Generates JSON Schema                              |
| `json_object`         | Requests JSON-formatted output                     |
| Tokens                | Measure input and output text processed by the LLM |
| `json.loads()`        | Converts JSON string into Python dictionary        |
| `**data_file`         | Unpacks dictionary values                          |
| `Ticket(**data_file)` | Creates and validates a Pydantic object            |
| Dot Notation          | Extracts individual model attributes               |

**Final Understanding:** This project demonstrates how to convert unstructured customer text into structured JSON, validate it using Pydantic, and extract individual information as Python variables.

**Small technical note for future improvement:** A phone number is generally better stored as `str` rather than `int`, because phone numbers are identifiers, may contain leading zeros, and can include `+` country codes.
