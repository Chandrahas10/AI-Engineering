# Prompt Engineering – Fundamentals

## 1. Project Overview

This project demonstrates the fundamentals of **Prompt Engineering** using the Groq API and the `openai/gpt-oss-20b` language model.

The objective is to understand how structured prompts influence LLM responses and how to control model output for specific tasks.

The implementation demonstrates an **issue classification system** that categorizes user complaints into predefined categories.

## 3. Prompt Engineering Fundamentals

The project demonstrates six important components of prompt engineering.

### 1. Role

Defines the identity or perspective the LLM should adopt while responding.

**Example:**
```text
You are the support assistant at a mobile/computer company.
```

**Purpose:** Establishes the context and behavior expected from the model.

### 2. Task

Clearly defines what the LLM is expected to perform.

**Example:**
```text
You have to classify the issue into a category.
```

**Purpose:** Gives the model a specific objective instead of allowing an unrestricted response.

### 3. Constraints

Defines the rules and limitations the model must follow.

**Example:**
```text
Classify the issue into one of three categories:
billing, technical, return.
```

**Purpose:** Restricts the model's classification choices to predefined categories.

### 4. Output Format

Specifies how the model should structure its response.

**Example:**
```text
Your answer must be one word only.
```

**Purpose:** Produces consistent and predictable responses that are easier to process programmatically.

### 5. Zero-Shot and One-Shot Prompting

These techniques define how examples are provided to an LLM.

**Zero-Shot Prompting**

The model performs a task without receiving any examples.

Example:
```text
Classify this complaint:
My laptop screen is not working.

Expected output:
technical
```

**One-Shot Prompting**

The model receives one example before performing the actual task.

Example:
```text
Example:
Complaint: I want a refund.
Category: return

Now classify:
My laptop screen is not working.
```

**Purpose:** Examples help guide the model toward the expected classification behavior.

### 6. Fallback

Defines what the model should return when the input does not belong to any predefined category.

**Example:**
```text
If the issue is unrelated to the three categories,
return other.
```

**Purpose:** Handles unexpected or irrelevant inputs without forcing them into an incorrect category.

## 4. Prompt Structure

The project follows this structured prompt design:

```text
ROLE:
Define the model's identity.

TASK:
Specify what the model needs to perform.

CONSTRAINTS:
Define rules and available categories.

OUTPUT FORMAT:
Specify the expected response format.

EXAMPLE:
Provide an example (one-shot prompting).

FALLBACK:
Define behavior for unsupported inputs.
```

## 5. Implementation Workflow

1. Load environment variables using `python-dotenv`.
2. Retrieve the Groq API key from the `.env` file.
3. Initialize the Groq client.
4. Select the GPT-OSS-20B model.
5. Define the `llm_ans()` function to send prompts to the model.
6. Construct a structured prompt using the six prompt engineering components.
7. Send the prompt to the LLM through the chat completion API.
8. Extract and print the model-generated response.

## 6. Core Function

### `llm_ans(prompt)`

Responsible for communicating with the Groq API.

**Input:** A user-defined prompt.

**Processing:**
- Creates a user message.
- Sends the message to the selected LLM.
- Retrieves the generated response.

**Output:** Text response generated by the model.
